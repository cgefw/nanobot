# 单用户角色陪伴模式

基于 `cgefw/nanobot`，并随上游主线合并更新。保留原有 Agent、工具、Skills、MCP、模型设置和 WebUI 部署方式，新增角色卡与独立角色进程。

## 使用

在本目录安装依赖并构建原 WebUI：

```sh
uv sync --extra api --extra dev
cd webui
npm ci
npm run build
cd ..
uv run nanobot webui --config /你的路径/config.json
```

也可以继续使用原来的 `nanobot gateway --config ...`、服务管理器或容器启动方式；构建产物仍在 `nanobot/web/dist`。使用已有模型配置即可。补丁没有修改机器上的原有配置，也没有写入真实 API 密钥。

1. 展开侧栏顶部的角色下拉菜单，选择“创建角色”。页面上方可拖入或选择 JSON / PNG / CHARX，预览后确认导入；下方点击“创建 Agent”，填写名称以及 `AGENTS.md`、`SOUL.md`、`USER.md`，再点击“创建并打开”。文件内容留空时使用项目默认模板。
2. 从角色下拉菜单或“设置 → 角色”打开角色。未启用 QQ 的角色在打开时启动进程。
3. 新聊天显示角色开场白，可以在发送第一条消息前选择备选开场白。发送时将选中的开场白保存到历史。
4. 右上角书本按钮打开角色设定抽屉。原有工具、Skills、自动化、设置入口仍保留。
5. 在“设置 → 角色”中打开或停止角色，聊天记录不会删除。角色页进入管理、创建或导入时会自动返回主实例；各角色的其他设置仍独立。
6. 在“设置 → 角色”中点击“删除”，确认后停止该助手并永久删除其独立实例目录，包括配置、提示词、聊天、记忆和附件。导入角色及自定义 Agent 均支持；默认助手不提供删除入口。外部项目目录和原始角色卡文件不会删除。
7. 更新已导入的角色：右上角书本按钮 → “更新角色卡” → 选择或拖入新版 JSON / PNG / CHARX → 预览 → “确认更新”。角色 ID、聊天、记忆、工作区和渠道配置保留，后续消息读取新设定；带头像的更新（PNG、含主图标的 CHARX 或内嵌 data URI 图标）替换头像，否则保留现有头像。原生 Agent 继续直接编辑三个 Markdown 文件。

默认助手使用原有配置和历史。角色的模型、工具和 MCP 配置在导入时继承父配置，之后可以分别调整。内置 Skills 继续可用；原工作区自行安装的 Skills、Apps 和用户文件不会自动复制到角色工作区，可通过原有界面安装或选择需要的项目目录。每个角色的用户资料和长期记忆也独立保存。

手动创建的 Agent 使用原生工作区提示词机制，不生成角色卡，也不启用角色扮演提示或角色开场白：`AGENTS.md` 保存工作规则，`SOUL.md` 保存身份和表达风格，`USER.md` 保存用户资料。创建后可通过聊天右上角书本按钮分别编辑，保存后在后续消息中读取。选定其他项目时，`AGENTS.md` 按原有规则使用该项目的文件；`SOUL.md`、`USER.md` 仍使用 Agent 工作区中的文件。记忆维护沿用原有 Agent 行为。

Agent 的名称保存在独立配置的 `roleplay.agentName` 中，Markdown 文件保存在其 `workspace/` 下，复用已有进程管理与切换界面。QQ 默认未启用，空闲压缩保持关闭。已导入角色卡继续使用原有角色卡机制。提示词编辑只允许这三个固定文件，沿用原有原子写入，内容总量不超过 1 MiB，并受当前模型上下文预算限制。

## QQ 官方机器人

先切换到需要连接的角色，再进入“聊天平台 → QQ”，使用原有界面安装 QQ 依赖、填写该机器人的 AppID、Secret 和访问限制并连接。每个角色使用独立机器人账号，凭证保存在该角色的配置中；新导入角色不会复制默认助手的 QQ 凭证。使用 QQ 官方 WebSocket 长连接，无需增加公网回调地址。

QQ 与网页保留各自的会话，共用当前角色的设定和已保存的长期记忆。角色间的配置、会话、附件和记忆保持独立。私聊及已有群聊功能沿用原 QQ 适配器，不增加主动问候。

“聊天平台 → QQ”的行为设置中可关闭“发送确认消息（Ack）”（`ackEnabled`），保留已填写的确认文案；将 `ackMessage` 留空也仍可关闭。进度消息和工具提示默认关闭，思考内容不发送到 QQ；网页显示不受影响。

需要渲染 Markdown 时，在当前角色的 QQ 设置中将消息格式设为 Markdown（`msgFormat: "markdown"`）。此选项由每个角色独立保存，新角色不会继承其他角色的 QQ 设置。普通回复沿用 `msg_type: 2` 和 `markdown.content`，流式回复使用 `content_type: "markdown"`；QQ 只支持[官方列出的 Markdown 子集](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html)。

流式输出默认开启（`streaming: true`），使用 QQ 官方私聊流式接口的 `replace` 模式：每一帧携带当前完整回复（QQ 只接受不断增长的内容），合并短时间内到达的片段，最多约每 0.5 秒更新一次，结束帧（`input_state: 10`）携带完整回复，从不为空。群聊、关闭流式输出或接口不可用时发送完整回复。若中途接口失败，QQ 中可能同时留下部分流式内容和完整回复。缓冲随当前回复长度线性增长，正常结束后释放。

已启用 QQ 的角色会随主服务启动；关闭网页不影响连接，主服务仍需保持运行。在“设置 → 角色”手动停止会保存 `roleplay.autoStart: false`，之后主服务重启也不会恢复它；再次打开角色会恢复为 `true`。该字段默认 `true`，仅用于恢复启用 QQ 的角色，不会启动所有导入角色。主服务退出只释放子进程，不改变此设置。某个角色启动失败不会阻止其他角色恢复，可检查该角色与主服务日志后重新打开。

## 空闲压缩

`agents.defaults.idleCompactAfterMinutes` 的默认值由 `15` 改为 `0`。关闭时直接跳过会话扫描；手动压缩和上下文容量压缩照常可用。

新导入角色会固定写入 `idleCompactAfterMinutes: 0`，不继承主实例的空闲压缩阈值。

**已有配置如果明确写了 `15`，请将它改成 `0`。** 为避免覆盖用户配置，不自动迁移已有显式值。周期 Dream 是另一项既有的记忆维护机制，不会因为这次默认值调整而关闭。

## 角色卡范围

- JSON / PNG / APNG / CHARX：V1、V2 常用字段与 V3（`chara_card_v3`）。PNG 同时含 `ccv3` 与 `chara` 时优先 `ccv3`，APNG 动画帧之后写入的数据也能读取。CHARX 读取压缩包根目录的 `card.json`。`spec_version` 高于 3.0 时导入照常进行并提示新版本特性可能不受支持。
- V3 资源：使用 `type: icon` 且 `name: main`（或唯一图标）的主图标作头像，支持 `ccdefault:`（PNG 卡片自身）、`embeded://`（CHARX 内文件）和 base64 `data:`；不下载远程链接。背景、表情、用户头像等其他资源不使用，CHARX 中的资源文件不另存，导入时提示。
- V3 字段：`nickname` 替代 `{{char}}`；作者说明按界面语言选用 `creator_notes_multilingual`；`group_only_greetings` 只用于群聊，单用户模式不使用；`source`、创建/修改时间随原始 JSON 保存。
- AICC：支持人物设定、开场白、提示词和世界书基础字段；兼容 PNG 尾部角色数据。原始数据保留，群聊开场白与深度提示定位暂不支持。
- 支持名称、描述、性格、场景、开场白、备选开场白、对话示例、system prompt、post-history instructions。post-history instructions 每轮放在系统提示末尾，不作为单独消息写入聊天记录。
- 宏（大小写不敏感）：`{{char}}`、`{{user}}`、`{{original}}`、旧式 `<char>` / `<bot>` / `<user>`，以及 V3 的 `{{random:A,B}}`（`\,` 转义）、`{{pick:A,B}}`、`{{roll:N}}` / `{{roll:dN}}`、`{{reverse:A}}`、`{{// 注释}}`、`{{comment:A}}`、`{{hidden_key:A}}`，可嵌套；未知宏原样保留。随机宏在角色卡加载时求值一次，开场白预览、保存的开场白与系统提示保持一致，直到角色卡变化；`pick` 对相同文本取相同结果。`{{user}}` 默认是“用户”，可在配置中设置 `roleplay.userName`。
- 世界书：启用开关、常驻条目、关键词、第二组关键词、大小写、优先级、插入顺序与位置、扫描深度、token 预算。没有第二组关键词的 selective 条目按主关键词匹配（SillyTavern 默认导出即如此）。
- V3 `use_regex`：`/pattern/flags` 形式的关键词按正则匹配（支持 `i`、`m`、`s`），无效正则不匹配；其他关键词仍按普通文本匹配，兼容 SillyTavern 对所有条目标记 `use_regex` 的导出。正则使用带超时的 `regex` 库，每轮总耗时不超过 0.25 秒，恶意回溯不会卡住对话。
- V3 装饰器：条目开头的 `@@` 行在发送前去除，并按规范尝试 `@@@` 备选。支持 `@@activate`、`@@dont_activate`、`@@scan_depth`、`@@additional_keys`、`@@exclude_keys`、`@@position`（`before_desc`、`after_desc`、`personality`、`scenario`）、`@@depth` 和 `@@role system`。世界书放在系统提示中而不插入聊天记录，因此 `@@depth` 采用规范的退化规则：深度不超过当前消息数时放在系统提示末尾（post-history instructions 之前），否则放在角色设定之后。需要逐聊天状态或开场白/用户头像跟踪的装饰器（如 `@@activate_only_after`、`@@keep_activate_after_match`、`@@is_greeting`）被忽略，导入时提示。
- 保存原始 JSON。PNG / CHARX 提取的头像缩至最大 512 像素并去除元数据，只解码 PNG、JPEG、WebP、GIF。
- 不执行卡片脚本，不支持递归世界书扫描、概率等扩展规则或 PNG 的 `chara-ext-asset_` 资源块。扩展字段保留，但不声称与 SillyTavern 完全兼容。
- 上传上限 24 MiB（为 CHARX 内的资源留出空间，base64 后仍低于默认 36 MiB WebSocket 帧），解码 JSON 上限 1 MiB，头像原图最多 1600 万像素，角色最多 100 个。过长固定设定会在导入时拒绝。

固定角色设定替代普通 SOUL 提示。Dream（包括定时运行和手动 `/dream`）不带角色人设，使用专门的维护提示，只能写入用户资料与记忆，不可修改 SOUL、角色卡或 Skills；聊天中的正常工具权限保持原样。摘要保留约定、偏好、共同经历和场景，并区分虚构事件与真实事实。

## 数据和部署

```text
配置文件所在目录/
  config.json
  characters/<随机 ID>/
    card.json         # 导入角色卡时存在；原生 Agent 不创建此文件
    avatar.png         # PNG 卡片可选
    config.json       # 独立模型、工具及工作区设置
    workspace/        # AGENTS.md、SOUL.md、USER.md、memory/ 等
    sessions/         # 独立会话
    logs/、run/       # 复用原有网关进程管理
```

浏览器只访问原网关。`/_characters/<ID>/...` 转发 HTTP 和 WebSocket 到仅监听 `127.0.0.1` 的角色子网关；不要求为每个角色开放公网端口。已有反向代理需同时转发这个新路径并支持 WebSocket，不能只放行 `/api` 和 `/webui`。主网关继续使用现有登录/令牌/可信代理机制，转发时保留远程来源限制，避免把远程浏览器当成本机。子网关只信任主网关在每次启动角色时随机生成的代理断言头；本机其他进程直连子网关端口时，仍需主网关的引导密钥和令牌。

角色进程复用现有 `GatewayRuntime` 和客户端租约；关闭主网关会释放角色进程，异常退出沿用原有孤儿回收机制。切换角色不会停止其他角色，运行中的角色可在“设置 → 角色”中显式停止。初次导入时不启用其他渠道，避免重复连接父实例的 Telegram 等账号；不复制心跳任务，所以没有新增的主动问候。

## 改动与复杂度

新增 `nanobot/roleplay/` 三个小模块（卡片、进程管理、转发）和前端角色组件；原 Agent 只接入角色上下文、记忆限制、开场白与压缩默认值。

- 未启用 QQ 的角色仍按需启动；启用 QQ 且允许自动启动的角色在主服务就绪后恢复。角色配置只在启动恢复时扫描一次，扫描为 O(N)，运行内存随实际运行角色数增长。
- 角色卡按文件修改时间与大小缓存；解析、世界书排序和 token 估算只在卡片变化时执行。
- 世界书只扫描最近若干条消息与当前输入，最终匹配文本限制为 16,384 字符。默认扫描最近 4 条、预算 2,048 tokens；开销不随整个历史长度增长。
- 设世界书键数为 K、扫描字符数为 W、命中条目为 E，匹配约为 O(K × W)，命中排序 O(E log E)；K、W、E 都有输入上限。没有复杂索引或新的数据库。
- 角色查找和已启动进程路由用字典 O(1)；只有角色列表初次加载需要读取各角色文件。
- 切换角色采用整页重连，直接清空进程内前端缓存；会话相关浏览器存储按角色分区。附件与 Markdown 媒体地址也路由到对应角色。
- 主机在 WebUI 契约中声明可选能力 `webui.characters.v1`，WebUI 只在主机声明该能力时显示角色切换、角色设置和角色设定入口。通过本地客户端连接的远程主机不会转发 `/_characters/` 路由，因此不显示角色界面。

## 验证

包含角色卡解析、头像清理、缓存、世界书匹配、Dream 写入边界、禁用压缩不扫描、数据隔离和真实多进程网关测试。真实网关测试覆盖开场白持久化/重放、角色之间的历史隔离、令牌隔离、伪造代理头与远程权限、停止进程。

前端经过 TypeScript/Vite 生产构建、相关 Vitest 回归，以及 Chrome 实际操作检查：导入预览、确认导入、切换角色、切换开场白、打开设定抽屉。模型调用仍沿用原实现；尚未使用你的真实模型/API 配置评估角色扮演效果。

本次 QQ 显示与流式选项、角色卡更新及列表加载恢复已通过接口模拟和组件回归，覆盖 Markdown 请求结构、流式降级、更新时保留数据及手机窄屏/软键盘布局。尚未完成这些新增功能的 QQ 真实账号收发和手机实机检查。角色列表仅合并正在进行的鉴权请求，展开切换器会重新加载；加载失败保留已有列表并提供重试。
